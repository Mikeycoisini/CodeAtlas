## UX01 本地目录选择与导入

### 现状和原因

D:/CodeAtlas/CodeAtlas前端/src/App.tsx 中 LOCAL 分支直接读取 importPath，并向 /imports 提交 path。点击“本地目录”只切换 importSource。界面文字“选择目录”与实际输入方式不一致。

浏览器的 showDirectoryPicker 返回目录句柄。现有后端接收的是本机绝对路径，两者需要适配。不得把 handle.name 或 webkitRelativePath 当作绝对路径。该浏览器 API 还要求用户交互触发，并具有兼容性限制。[MDN 目录选择 API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)

### 建议实施路线

沿用当前本机后端扫描模式，增加受保护的本机目录选择适配器。用户点击“本地目录”时调用本机选择接口，后端在交互式桌面进程中打开系统目录对话框，返回选择结果及可导入路径。Java Swing/JavaFX 或原生桥接的可行性需先小范围验证，检查 Windows 前台焦点、headless 状态和运行账号。

如果部署进程缺少交互式桌面，界面应提供明确的手填路径回退。另一条浏览器读取并上传文件的路线需要新增上传、扫描与快照身份协议，须单独确定采用后再实现。

接口草案为 POST /api/local-directories/select，返回 selected/cancelled/unavailable 和 path。请求沿用会话令牌、来源检查及本地访问限制。只允许固定的目录选择动作，使用参数数组启动原生适配程序。对话框单实例互斥，支持超时、用户取消和重复点击。目录选择不读取整个文件树。

选中后回填真实路径并展示授权范围。授权确认后复用现有导入及快照任务流程，允许用户直接继续导入。GitHub 保持地址和分支手工输入。

### 验收

- 从导入弹窗点击本地目录可打开系统目录选择器，取消后可继续操作。
- 中文、空格、长路径可正确导入，选择文件应被拒绝。
- 不支持原生对话框时显示原因与输入路径回退。
- GitHub 导入流程回归通过，未选目录或未授权时无法创建快照。
- 目录扫描继续执行既有敏感文件过滤、数量大小限制、链接边界和来源身份规则。

## UX02 关系图可读性与导航

### 现状和原因

相关文件为 D:/CodeAtlas/CodeAtlas前端/src/graph/layout.ts、GraphCanvas.tsx、GraphEdgeView.tsx 和 GraphWorkspace.tsx。

layoutGraph 的 ranksep 固定为 240，自环按数量额外扩大节点占位。GraphCanvas 对全图 fitView，自环时使用包含最大自环半径的 fitBounds，并允许缩放至 0.1。大图包围盒越大，适配后的文字越小。大量平行边和证据标签同时展示，使视觉密度进一步升高。

布局缓存记录在 sessionStorage。仅修算法而继续恢复旧坐标会造成用户仍看到旧图，需加入布局版本及节点、边结构摘要。截图中页外关系很多，单纯提高节点上限会进一步损害阅读体验。

### 开发要求

- 初始视图按项目模块或包聚合，只显示当前层级的直接依赖。点击节点下钻类型关系或一跳调用，提供面包屑返回。
- 聚合边保留关系类型、状态和证据数量，选中时显示原始边与来源。自环默认显示计数，展开后查看具体证据。
- 提供适应全图、可读比例、聚焦选中节点、展开相邻节点和全屏。默认根据节点数量选择初始范围，保留全图总览入口。
- 常态下边标签按选中或悬停展开。连线采用明确端口和分层方向，双向、平行及跨层边分离路由。
- 先验证当前 Dagre 在聚合模型上的效果，再评估 ELK compound 布局。第三方库升级须锁定版本并检查许可证。
- 缓存身份包含 snapshotId、generationId、视图、过滤条件、布局版本和图结构摘要。重新布局应清除对应坐标及视口。
- 算法与排序保持确定性。分页、截断和未知关系继续提供统计与列表入口。

### 验收

使用截图中的 EquipOps 快照，以及小、中、大三种固定样本。记录节点数、边数、自环数、画布尺寸和初始 zoom。建议默认聚合图控制在 10～30 个可读节点，普通桌面初始标签视觉字号至少 12px。该阈值需以实测截图确认。

验收包括节点无覆盖、主链方向稳定、焦点可恢复、源码跳转身份正确、旧缓存失效、深浅主题及窗口尺寸变化。保留修复前后截图和布局耗时、主线程阻塞记录。

## UX03 系统架构视图对齐参考 HTML

### 目标与原因

用户明确以第五张图和 D:/CodeAtlas/codeatlas-architecture.html 为目标。参考文件具有部署边界、按角色配色的节点、协议标注、折线路由、主题、引导视图、演示和导出等表现。

当前 ArchitectureWorkspace.tsx 的 layout 为固定坐标布局。模块依次纵向堆叠，组件放在固定列，未归属组件按四列排布，画布宽度固定为 1240。组件行间距为 92，模块步长同时取决于子组件数量，可能出现邻组或未归属节点互相占位。未归属组件行数没有计入 contentHeight 的主要计算路径，需补充裁切测试。当前样式还需核对详情面板占位与滚动容器，截图已有面板遮挡画布表现。

参考 HTML 为针对 CodeAtlas 自身整理的架构。导入其他项目时需要从该项目的快照识别实际应用、技术与外部依赖，复用参考文件的布局及交互能力。架构的数据生成、可追溯证据与视觉渲染共同构成此项交付。

### 分层投影

1. 系统视角默认展示应用、数据存储、外部服务、浏览器或调用方及部署边界。组件详细信息通过下钻查看。
2. 应用视角按 API、业务服务、持久化、异步任务和基础设施分组，展示主要依赖。
3. 模块视角显示业务模块内部组件，关联细节可跳入代码关系图。
4. 代码关系图与架构图共享固定快照及来源选择，提供相互导航。两个页面采用各自明确的默认层级和布局策略。

### 数据与渲染

- 检查后端 ArchitectureService 及投影构建逻辑，明确 application、module、component、external、datastore 的归属和视角过滤。
- Maven 模块、启动类、配置文件及注解作为识别证据。浏览器、第三方服务、数据库和协议只有在存在依据时生成，并记录规则、来源与状态。
- 配置声明连接标记为配置证据，运行可达性另行验证。动态目标缺少证据时显示未知。
- 技术标签、职责摘要、边界和连线均引用投影中的节点 ID。AI 可生成辅助描述，需保留生成来源及不确定性。
- 抽取独立渲染器，接受结构化投影及布局结果。将参考 HTML 中的网格、配色、折线、标签、焦点、高亮、引导与导出能力映射到动态数据。
- 首批视觉验收以第五张图的系统总览为基线。引导步骤根据当前图的真实节点生成，导出 HTML/SVG 与页面共用投影和布局。
- 明确架构详情面板的固定占位或可收起规则，画布可缩放平移，窗口变化后重新适配。
- 检查根目录参考文件与 docs/architecture 下副本的差异，记录实际选用版本及 SHA-256，避免后续实现引用不同模板。
- 检查参考模板内嵌脚本与第三方许可，导出转义所有动态内容，验证 CSP、离线运行及敏感配置脱敏。

### 验收

CodeAtlas 样本可展示前端、Java 后端、Python AI 服务、MySQL、本地数据目录、GitHub 和 Docker 中有证据支持的部分。EquipOps 样本依据其实际项目结构生成。保存两套样本的系统总览、下钻、选中证据和导出截图。验证参考图的视觉特征、动态数据绑定、缩放和主题切换，同时检查未知节点及截断提示。

## UX04 代码分析入口修复

### 源码确认

AnalysisWorkspace 接收 App 的 selectedSymbol。为空时提前返回只有提示文案的页面，因此未选择符号时流程、时序、UML 标签都不可见。当前截图符合该分支表现。已有 flow、sequence 和 uml 请求与渲染逻辑，全部后端功能失效需要另行复现。

### 开发细节

- 页面内直接提供项目、快照、索引代次、文件和符号选择，方法支持流程图及静态时序，类型支持 UML。
- 复用源码查询 API 和来源选择组件。SourcePicker 目前硬编码 METHOD、前 50 条，需扩展类型过滤、文件选择和分页能力。
- 为 analysis 明确保存 symbolId 及 generationId 的 URL 状态。刷新、复制链接、后退、切换项目均重建合法选择。
- App 当前 selectedSymbol、文件路径和 URL 身份可能不同步，需追踪选择与恢复 useEffect 顺序。所有请求基于同一完整身份元组，过期请求应取消。
- 针对 enum、record、annotation、constructor 等符号明确支持矩阵及降级说明，避免出现无响应按钮。
- 加入 loading、空结果、索引未完成、符号失效和 HTTP 错误的可恢复状态。

### 验收

直接从侧栏进入且没有探索历史也能选符号。选择方法可分别生成流程及时序，选择类型可生成 UML。以浏览器网络记录证明请求发出且身份正确。刷新、深链接、新旧快照、重新索引和快速切换样本均应覆盖。保留既有控制流复杂语法限制并验证提示内容。

## UX05 AI 源码选择与用途路由

### 原因

AiAssistantWorkspace 只有 hasSource、onOpenAi 和 onNavigate，内部无项目或源码选择器。hasSource=false 时“先选择源码”的点击逻辑没有后续动作。App.currentSource 又依赖已选 selectedSymbol，因此只打开文件也可能缺少 AI 来源。

解释和项目说明目前都调用同一个 onOpenAi，未传递用途。AiPanel 默认 purpose 为 METHOD_EXPLANATION，项目说明入口需要验证实际是否预选 PROJECT_NOTE。

### 开发细节

- AI 工作区直接提供已导入项目、快照、文件、类型、方法与行范围选择，支持多个来源及各用途所需的数量限制。
- 将 EvidenceSource 与 SourceSelection 的转换集中校验，携带 projectId、snapshotId、generationId、fileId、symbolId、行范围和摘要，文件级来源也可使用。
- 切换项目或快照时清空旧上下文与授权预览。旧生成历史继续绑定原始来源。
- 每个能力卡片显式传入 operation 和 purpose。项目技术说明可选择构建文件、配置及多个入口，敏感值必须脱敏。
- 离线、未配置、来源未索引和生成失败均展示具体原因与恢复操作。

### 验收

没有任何探索选中状态时，进入 AI 助手可选已导入源码并预览上下文。解释、追问和项目说明使用对应用途。切换项目、快照、代次后不会沿用旧来源。真实模型验收需独立记录模型、样本授权、质量标准与费用边界。

## UX06 AI 自动生成学习内容

### 现状与产品差距

AiPanel 已有解释、技术笔记、项目说明等 purpose，并可保存为文档或知识。TrainingAiPanel、PracticeAiPanel 和 GuideAiPanel 已有各自上下文、生成及采纳路径，GuideAiPanel 需要现有 guide，实践反馈需要真实提交。

统一 AI 页面主要导航到这些页面。用户还需先手工创建任务或引导、补充来源，再找到内部 AI 按钮。生成结果缺少一条直达知识点、卡片文案和相关学习对象的完整流程。现有生成能力需复用并补齐编排。

### 目标流程

选择源码及用途 → 自动准备有界上下文 → 展示外发预览与授权 → AI 生成结构化内容 → 展示可编辑结果 → 一次保存所选知识、卡片、任务、引导或技术说明。

“一键生成”应自动完成内容起草。保存模式可提供明确的生成并保存操作，用户无需先手填正文。敏感源码外发继续执行已有授权链路。

### 用途交付表

| 用途 | AI 生成内容 | 保存对象与前置条件 |
|---|---|---|
| 源码解释与追问 | 解释、业务作用、风险、知识摘要、问答卡片候选 | 文档、知识、卡片，引用固定源码及追问父记录 |
| 源码理解出题 | 题干、题型、提示、答案、评分规则、知识点、复习卡片 | 训练任务和题目版本，可自动创建任务草稿 |
| 实践反馈 | 根据提交差异与测试证据生成反馈、薄弱点和复习卡片 | 关联真实 submission、测试结果及知识证据 |
| 六步引导 | 六步问题、建议动作、预期证据和相关知识卡片 | 自动创建引导草稿并复用现有六步状态机 |
| 项目技术说明 | 技术栈、架构职责、主要链路、风险及知识卡片 | 项目说明文档和来源关联知识 |

实践反馈缺少提交时提供选择或创建实践的入口，显示前置条件。AI 反馈与测试实际结果分别记录。六步建议可自动生成，各步实际执行和验证依据真实学习记录更新。

### 后端与一致性

- 先复用现有 context、generation、apply-suggestion 和学习对象创建接口，评估是否需要生成产物清单及一次采纳编排接口。
- 结构化输出须按用途验证 schema、长度、题型、答案和来源引用。输出中的源码引用必须来自已授权上下文。
- 知识与卡片建立关联，记录 generationId、来源、模型及版本。卡片创建复用现有复习调度初始化逻辑。
- 同一生成结果的多产物采纳使用内容摘要和幂等键。重复点击、超时重试、部分失败不得重复生成卡片或产生无归属记录。
- 如采用多接口保存，明确可恢复的部分完成状态。如新增事务编排，先检查现有 MutationService 与各领域服务的事务边界。
- 练习判定、个人掌握及六步完成状态依赖真实证据。AI 辅助建议需保留其来源与状态。
- 限制来源数量、上下文和输出大小，校验提示注入、模型输出脚本及路径内容。模型密钥仅保存在本机服务配置。

### 验收

五种用途分别从 AI 工作区新入口跑通。用户无需预先手写正文即可获得对应内容。知识和卡片落库可查询，卡片可进入复习。模拟模型测试覆盖协议和失败路径，真实模型另评事实准确性、引用正确性、教学质量、题目可回答性和卡片粒度。

## 实施顺序及交接

1. 先保存现有代码状态及截图基线，记录运行端口和已有进程，按 UX01、UX04、UX05 补齐基本入口。
2. UX02、UX03 共用快照身份和证据投影，分别完成代码图与系统架构图的布局和导航。
3. UX06 复用已有 AI 服务和版本化模型，完成跨领域保存一致性及失败恢复。
4. 最后进行真实浏览器端到端验收，复核生产构建、HTML/SVG 导出、MySQL 持久化和重启。

当前机器近期出现 Windows 错误 1455。采用顺序测试及有限 JVM 堆运行，记录内存与分页空间，避免并发启动大量 Java、浏览器和 MySQL 测试实例。大图性能须记录样本规模及资源条件。

每项交付均需包含代码位置、接口或迁移变化、自动化测试结果、浏览器截图和仍待验证边界。新增迁移遵守现有 Flyway 版本序列。对 GitHub 项目和 archify 模板进行复用时记录来源、版本、许可证及改动范围。

本说明列出的修复及体验增强应逐项追踪，阶段归属在发布计划中明确记录。用户当前目标包括图形质量与完整操作路径，验收应覆盖完整路径和第五张图的视觉标准。
