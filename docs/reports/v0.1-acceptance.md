### 覆盖场景

- 重载身份、事务注解、方法位置和语法错误文件隔离。
- 无效 UTF-8 文件保持诊断，重复限定类型的调用保持 UNRESOLVED。
- 非 Git、Git clean、Git dirty 来源区分，配置外部过滤器时返回 UNKNOWN。
- 原目录脚本保持静态数据，导入过程不执行项目脚本。
- 快照内容固定、同内容重复导入去重、源码变化后旧字节保留。
- 大小限制、数据目录重叠、Windows junction 和扫描中源码变化。
- 实际 HTTP 导入、查询、文件内容、重建、历史代次恢复。

- 数据库提交确认丢失时保留可能已发布的快照，启动时再核对无引用目录；Git linked worktree 的 .git 文件保持忽略。
- 失败恢复后的重试、无 Java 文件的空索引、本机会话及跨来源拒绝。
- 通过界面导入新项目、搜索重载、定位证据、浏览器后退、刷新恢复。

## 实施决策与边界

- 用户确定 MySQL 路线和前后端分离目录。实施中选择 JDBC/Flyway、文件快照、单进程队列、数据目录文件锁和只读 Monaco。
- 测试使用 H2 与独立 MySQL 实例。用户常用数据库的最终配置和真实业务项目尚待提供。
- Git 查询不采用用户全局 excludesFile / attributesFile，采用仓库自身规则及快照策略，以减少本机配置影响。存在相关过滤器、子模块或查询警告时保留 UNKNOWN。
- 缺失的 Maven 依赖、生成代码、Lombok、反射、Spring 代理及复杂装配可能产生未解析关系。框架推断规则尚未引入。
- Java 语法支持范围为 Java 21，源码查看与解析支持 UTF-8。
- Windows 祖先目录的恶意并发替换仍属于路径式访问的系统边界。已实施重解析点、属性和二次内容检查，导入时使用稳定工作区。
- 当前目录没有 Git 仓库元数据，源码以文件形式交付，未创建提交。
