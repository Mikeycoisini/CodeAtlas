# CodeAtlas V0.2 设计

状态为用户已批准并完成实施验收。日期为 2026-11-14。

依据 PRD V1.0、总体与步骤实施计划 V1.1、scope-v0.2.md，以及当前 V0.1 源码。用户已选择新增 Python/FastAPI 服务，并指定参考 D:/HealthAi-server 配置。

## 目标

完成选择源码、预览外发范围、授权生成解释、校验引用、保存可编辑文档、提炼知识并创建卡片的链路。用户也可直接管理手工文档、知识与卡片。数据持久化，并与准确的源码快照关联。

范围对应 V02-01 至 V02-07。复习调度、实践提交和学习引导依照后续版本计划推进。V0.1 的导入、索引、源码浏览及历史引用继续作为正常入口。

## 已确认路线与备选

用户选择 React、Spring Boot/MySQL 与新增 Python/FastAPI 服务。Java 后端负责授权、源码检索、证据校验、任务及数据持久化，Python 服务负责模型提供商适配和输出结构检查。

曾比较独立 FastAPI 与直接在 Spring Boot 内接入模型。独立服务可单独演进模型接口和 Python 实现，运行时需要同时启动 Java 与 Python。直接 Java 接入的运行配置更集中。用户选择原技术方案中的独立服务。

建议将新服务放在 D:/CodeAtlas/CodeAtlasAI，与现有 CodeAtlas后端 和 CodeAtlas前端 平级。继续采用本地单用户运行，Python 服务监听 127.0.0.1:8001，Java 服务维持 8080。

## 配置参考与真实调用范围

静态读取 HealthAi-server 的配置得到默认供应商 deepseek、模型 deepseek-chat、接口 https://api.deepseek.com、temperature 0。该目录包含已配置的 DEEPSEEK_API_KEY，部分 LLM_API_KEY 配置为空。仅记录配置名与是否有值。

新服务支持 CODEATLAS_LLM_PROVIDER、CODEATLAS_LLM_MODEL、CODEATLAS_LLM_BASE_URL、CODEATLAS_LLM_API_KEY，以及可选的 CODEATLAS_LLM_ENV_FILE。环境变量优先，其次读取用户指定文件中的白名单配置项，最后采用公开默认值。兼容 LLM_* 和 DEEPSEEK_API_KEY 名称。环境文件作为纯配置解析，密钥只在服务内存中使用。

指定 HealthAi-server 环境文件为可选启动方式。产品目录只提交占位示例，凭据由原本机配置提供。服务对浏览器返回供应商、接口主机、模型、配置指纹和就绪状态，保持密钥在本机进程中。

当前 DeepSeek 官方文档列出的模型名称与本机默认值存在变化，模型名保持可配置，实际支持情况由获授权的模型列表查询和一次小范围请求验证。缺少配置、鉴权失败或模型不可用均形成明确状态。

真实联调建议只发送已有的公开 Spring PetClinic 固定版本中用户预览选定的方法及最少关联片段，单次输出上限建议 4096 tokens。真实请求仍通过产品的外发预览和授权链路。私有业务项目的外发范围在使用时由用户另行选择。

最初的带凭据模型查询被自动审批拒绝且保持未执行。随后用户明确授权使用参考配置中的密钥连接官方接口、查询模型，以及对公开 PetClinic 预览片段进行小范围真实联调。确定性回归另行使用受控模拟服务。

## 模块职责

### Java 后端

- SourceEvidenceService 统一读取、校验和裁剪快照源码，复用现有文件与符号身份。
- LearningStore 负责文档、知识、卡片、来源、授权与生成记录的事务和查询。
- AiContextService 构造可复核的最小上下文及授权预览。
- AiGenerationService 管理独立生成队列、任务状态、调用边界和结果校验。
- AiServiceClient 调用本机 FastAPI，限制超时与响应大小。
- LearningController 和 AiController 提供本机会话保护下的接口。

### Python 服务

- Settings 读取白名单配置，提供公开配置摘要与指纹。
- Provider 接口接受受控消息，首个实现适配 DeepSeek Chat Completions 的 JSON 输出。
- Pydantic 模型校验 Java 请求封装和模型结果的结构、字段长度与数量。
- FastAPI 只接收经过内部令牌校验的生成请求，提供本机状态端点。

模型调用输入由 Java 准备，Python 服务的模型接口只具有文本生成能力。源码、日志与模型输出以数据处理，外部请求使用启动时配置的目标。

## 外发预览与授权

1. 用户选定项目、快照、符号、输出用途、深度和问题，调用本地预览接口。
2. Java 验证项目、快照、代次和符号归属，构造不可变 PreparedContext。
3. 预览显示供应商、接口主机、模型、用途、相对文件路径、源码范围、片段全文、输入规模和输出上限。绝对项目根路径保持在本机。
4. 用户提交 ALLOW 或 DENY，保存独立授权记录。
5. 生成接口必须提供授权 ID 及幂等键，校验上下文摘要、配置指纹、有效期、用途与问题完全匹配。
6. 工作线程在外发边界再次检查授权和取消状态，记录外发开始时间，再调用本机 AI 服务。

PreparedContext 建议有效期 15 分钟。其摘要包含精确的 contextJson UTF-8 字节、问题、用途、深度和受限历史。提供商、模型或发送内容变化后重新准备预览。一次授权可绑定同一个幂等生成请求，重复传输返回原任务。

拒绝授权的记录保持 DENIED，生成请求返回授权错误，模拟提供商计数为零。取消发生在任务外发之前时同样保持零外发。外发之后取消为尽力终止，外部计算和计费可能继续，本机任务保留取消终态并丢弃迟到结果。

## 最小源码上下文

默认聚焦一个方法或构造函数，包含其精确范围、所属类型声明与必要导入信息。用户可选择添加有限的直接关联符号，最多 6 个来源。所有来源属于同一个明确快照和已发布代次。

建议输入预算为 24,000 字符及 64 KiB UTF-8 源码内容，聚焦方法建议上限为 10,000 字符。超过预算时返回可理解的范围错误，用户可以收窄内容。片段在预览确认后冻结。

每个来源保存 sourceId、projectId、snapshotId、generationId、fileId、相对路径、文件 SHA-256、可用 symbolId、行范围与片段摘要。AI 结果引用仅能关联此次准备的来源集合。

继续追问关联父生成记录，默认沿用相同快照。至多携带最近 4 轮受限历史，并在新预览中显示。扩展上下文或更换问题时形成新的摘要与授权。

技术笔记和项目说明可从用户明确选取的若干源码符号生成，使用同样的预算、来源与授权。生成结果显示所覆盖的源码范围，业务流程说明保留不确定项。

## 结构化解释与引用校验

统一结果包含 title、summary、keyPoints、explanation、citations 和 uncertainties。使用 DeepSeek 支持的 JSON 输出，并在提示中给出结构样例。返回空白、截断、非 JSON 或结构不匹配时记录对应错误。

每条模型引用包含 sourceId、filePath、startLine、endLine 和说明。Java 根据本机准备记录核对来源身份、项目/快照归属、文件路径及哈希、可用符号和授权片段范围。状态由服务器生成，取 VERIFIED 或 INVALID，并附原因。

无效引用保留可辨识状态，界面提供原因。有效引用可定位同一快照和代次的源码。模型生成的自评状态不参与服务器校验。引用位置正确与业务解释正确分别展示，解释内容允许人工修订。

模型输出采用 React 文本展示和受控编辑字段。原始响应按受限大小留存于生成记录，日志记录错误码、请求 ID、时长和用量摘要。

## 数据与迁移

使用 V2 增量 Flyway 迁移，保留 V1 的既有迁移文件。新增记录采用 UUID，时间使用 UTC。

| 实体 | 主要内容与规则 |
|---|---|
| EvidenceSource | 不可变项目/快照/代次/文件/哈希/符号/范围，唯一来源摘要 |
| Document | 标题、正文、类型、人工/AI 来源、生成记录 ID、revision、时间与删除状态 |
| Knowledge | 独立标题、原理正文、标签、revision、时间与删除状态 |
| Card | 可选知识 ID、问题、答案、解释、代码实例、用户笔记、标签、revision、时间与删除状态 |
| DocumentSource | 文档与 EvidenceSource 的关联 |
| KnowledgeSource | 知识与 EvidenceSource 的关联，可跨项目和快照 |
| CardSource | 卡片与 EvidenceSource 的关联 |
| PreparedContext | 精确外发文本、来源清单、配置指纹、问题、用途、深度、摘要与过期时间 |
| AiConsent | PreparedContext、ALLOW/DENY、时间及绑定的生成请求 |
| AiGeneration | 上下文、父生成记录、幂等身份、状态、结果、引用校验、用量、错误和时间 |
| MutationRequest | 创建操作的幂等键、请求摘要及结果身份 |

来源的快照与文件使用现有复合外键，符号引用使用代次与符号的复合身份，并以应用检查补全跨表归属。关联表通过外键约束持久化身份。

文档、知识和卡片采用软删除，正常列表过滤删除记录。删除知识后，独立卡片保存自身内容并展示知识关联失效状态。来源和历史生成保持可追溯。

编辑使用 revision 乐观锁，提交旧版本返回 409，界面保留本地编辑草稿。正文与关联来源在同一事务内更新，任一来源验证失败则整次提交失败。

创建操作使用幂等键和请求摘要，重复相同请求复用结果，同键不同内容返回 409。文档建议上限 64,000 字符，知识 32,000 字符，卡片答案 16,000 字符，其他字段设置明确长度及数量上限。

## 文档、知识与卡片操作

文档支持手工创建、保存 AI 解释、查看、编辑、搜索与删除。再次生成产生独立候选，用户明确保存时创建新文档，或以当前 revision 明确应用到现有文档。

用户可从文档提炼知识，将正文与来源复制为可编辑草稿。知识可以直接创建、修改、查找和删除，并通过来源选择器关联其他项目的准确快照。

用户可手工创建卡片，或从知识预填问题、答案和来源后编辑。卡片内容独立保存，支持搜索、编辑及删除。学习掌握状态和复习调度按 V0.4 计划实现。

## 生成任务与错误恢复

AI 任务采用独立的 QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED 状态，使用有界单工作线程队列。索引任务与生成任务分别查询和取消。

幂等请求只绑定一个有效生成任务。模型客户端默认单次发送，网络异常形成失败记录。进程重启时将未完成的生成标记 PROCESS_INTERRUPTED，由用户重新预览并授权重试。

生成结果及其引用校验原子保存。任务取消和结果发布通过相同任务锁协调，迟到结果保持取消终态。文档保存通过独立操作发生，生成失败时已经保存的人工内容继续可用。

错误至少包括 PROVIDER_NOT_CONFIGURED、AI_SERVICE_UNAVAILABLE、PROVIDER_AUTH_FAILED、MODEL_UNAVAILABLE、PROVIDER_RATE_LIMITED、PROVIDER_TIMEOUT、EMPTY_RESPONSE、INVALID_JSON、INVALID_RESPONSE_SCHEMA、CONTEXT_LIMIT、CONSENT_REQUIRED、CONSENT_DENIED、CONSENT_EXPIRED、CONSENT_SCOPE_CHANGED、REVISION_CONFLICT 和 PROCESS_INTERRUPTED。

默认外部请求超时建议 60 秒，Java 调用 Python 的超时稍长于提供商上限，模型响应最大 2 MiB。具体值由配置覆盖，并进入确定性测试。

## 接口概要

沿用 /api、本机会话、统一错误结构与 limit/offset 分页。

| 操作 | 接口建议 |
|---|---|
| AI 公开配置状态 | GET /api/ai/provider |
| 准备授权上下文 | POST /api/ai/contexts |
| 查看冻结预览 | GET /api/ai/contexts/{id} |
| 提交授权决定 | POST /api/ai/consents |
| 生成与继续追问 | POST /api/ai/generations |
| 查询生成记录 | GET /api/ai/generations/{id} |
| 取消生成 | POST /api/ai/generations/{id}/cancel |
| 文档管理 | GET/POST /api/documents，GET/PUT/DELETE /api/documents/{id} |
| 知识管理 | GET/POST /api/knowledge，GET/PUT/DELETE /api/knowledge/{id} |
| 卡片管理 | GET/POST /api/cards，GET/PUT/DELETE /api/cards/{id} |
| 源码来源校验与绑定 | POST /api/sources，GET /api/sources/{id} |

学习实体创建与更新接受来源 ID 集合，由服务校验归属。通过生成记录保存文档时由服务器取得校验后的来源，客户端只提交要保存的文本和明确的创建/更新意图。

内部 FastAPI 提供 /health、/internal/provider 和 /internal/generate，使用 CODEATLAS_AI_SERVICE_TOKEN 鉴权。Java 与 Python 通过同一启动环境获得该令牌，启动脚本可在本机进程环境中生成随机值。

生成封装包含请求 ID、上下文 JSON、其摘要、配置指纹与有效期。Python 再次核对摘要及指纹。服务路径和供应商地址来自本机配置，模型文本不参与路由选择。

## 界面

保留源码探索入口，在选中方法的证据面板增加解释入口。用户选择深度、用途或问题后打开授权预览，查看准确片段并允许或拒绝。生成过程显示状态、取消、错误与重新准备入口。

解释展示要点、正文、引用状态和不确定项，可跳回源码、继续追问、保存文档或提炼知识。

侧边导航新增文档、知识和卡片入口。各入口提供分页列表、搜索、创建、详情、编辑及删除。编辑器采用可访问的标题与正文表单，明确保存状态和版本冲突。来源选择器复用项目、快照、符号搜索，并展示固定版本。

URL 保存页面和实体身份。异步请求使用取消与身份检查，切换页面、项目或快照时避免迟到结果覆盖当前内容。用户选择来源跳转时恢复正确项目、快照、代次、文件与范围。

## 运行与本地边界

Java 的学习资料功能独立于 AI 服务的就绪状态。Python 环境采用专用虚拟环境与固定依赖版本，启动说明分别覆盖开发和打包运行。

新增启动帮助脚本仅设置所需白名单配置和本机服务令牌。HealthAi-server 的配置文件作为只读参考输入。模型密钥只由 Python 读取。

为支持文档正文，Java JSON 请求体上限建议调整为 1 MiB，并实际限制读取字节数，覆盖分块传输。各业务字段另有长度上限。Python 内部请求和响应采用同样的有界读取。

复用现有 Host/Origin 和本机会话保护，限制内部 AI 服务的鉴权与目标地址。日志覆盖错误码和请求 ID，正文与密钥保持在用户授权的数据存储及请求路径中。

## 验收

先执行既有 V0.1 回归，再验证 V1 至 V2 迁移及增量功能。固定模拟提供商通过实际 HTTP 边界返回正常、空白、错误 JSON、伪造路径、错误范围、超时、限额和恶意注释场景。

必须证明拒绝授权和外发前取消时提供商请求计数为零，上下文变化导致旧授权失效，重复请求保持一个有效生成，取消后迟到响应保持取消状态。

持久化覆盖文档/知识/卡片的增删改查、重启恢复、乐观锁冲突、重复创建、AI 失败后人工内容保存，以及同一知识关联两个不同项目。

浏览器从源码入口完成预览、拒绝、授权解释、引用跳转、保存文档、编辑、提炼知识和创建卡片，并直接测试手工入口及刷新恢复。

真实提供商联调以明确授权为前提，报告记录供应商、实际模型、范围、耗时、用量及结果。确定性模拟结果和真实模型结果分别保留实际状态。

交付 Java 后端、React 前端、新增 Python 服务、V2 迁移、API/来源/授权契约、配置示例、运行说明、测试与 docs/reports/v0.2-acceptance.md。

实施者可决定内部类名、文件拆分、兼容依赖补丁版本、样式细节和测试工具。供应商默认值参考本机配置，模型实际可用性由授权后的请求确定。影响源码外发范围、已有数据身份或用户保存内容的变更需同步设计和 ADR。
