# CodeAtlas V0.2 范围与验收追踪

日期为 2026-11-14，状态为设计已批准并完成实施验收，结果见 docs/reports/v0.2-acceptance.md。

依据上级目录 PRD V1.0、总体与步骤实施计划 V1.1 和初版技术方案。沿用已交付的前后端目录、MySQL、源码快照和索引代次。

## 交付目标

用户选择固定快照的方法，确认供应商、用途和外发范围后请求 AI 解释。解释显示源码引用的校验状态及不确定项，可保存为可编辑文档、关联独立知识点并创建卡片。文档、知识与卡片支持手工管理和搜索，重启后可以找回。旧引用继续指向原始快照。

## 需求追踪

| 实施任务 | PRD 需求 | 验收条件 |
|---|---|---|
| V02-01 授权与模型接入 | AI-01、AI-05 | 授权包含供应商、模型、用途与实际发送范围，拒绝或取消时外发计数为零，缺少密钥时有明确反馈，密钥保持在本机配置中 |
| V02-02 最小源码上下文 | AI-01、AI-02、KN-03 | 从符号检索固定快照的源码和有限关联证据，记录检索出处及预算，越界和归属错误被拒绝 |
| V02-03 解释与引用校验 | AI-01、AI-02 | 结构化输出包含要点、讲解、源码引用和不确定项，逐条校验项目、快照、文件、哈希、符号及范围，伪造或无效引用显示对应状态 |
| V02-04 文档管理 | AI-03、AI-04 | 创建、查看、编辑、搜索和删除笔记与讲解，保留来源，重新生成保存独立候选，用户修改和已保存文档在失败时继续可用 |
| V02-05 知识与项目案例 | KN-01、KN-03 | 独立知识点支持关联两个项目的多个源码位置，各自跳转到准确快照，编辑保留人工补充 |
| V02-06 卡片管理 | KN-02、KN-03 | 手工或从知识创建卡片，支持问题、答案、解释、代码实例、笔记与来源，增删改查及重启恢复通过 |
| V02-07 隐私与异常验收 | AI-02、AI-05、KN-03 | 覆盖空响应、超时、限额、结构错误、伪造引用、拒绝授权、恶意注释及并发编辑，提交实际验证报告 |

## 复用的 V0.1 能力

- Project、SourceSnapshot、SnapshotFile、IndexGeneration 和符号身份。
- 文件内容哈希、快照归属和历史代次查询。
- 本机会话与同源 API 边界。
- MySQL、Flyway、JDBC 事务和现有确定性测试环境。
- React 源码探索及 Monaco 证据定位。

## 实施约束

- AI 授权绑定实际请求上下文，重试和继续追问仍须满足有效授权范围。
- 源码注释作为待解释的数据处理，模型调用权限由应用接口限定。
- 引用可定位与解释事实正确分别表达。
- 用户文档编辑需要版本冲突处理，重复提交与生成重试需要明确幂等边界。
- 来源绑定项目、快照、代次、文件、内容哈希、可用符号与范围。
- 知识点独立于项目，来源以关联记录保存。
- 数据库迁移兼容 V0.1 的已有快照与索引。
- AI 服务故障时手工文档、知识和卡片仍可正常管理。

## 已确认设计决策

用户已选择独立 Python/FastAPI，并指定参考 D:/HealthAi-server 配置。静态核对的默认值为 DeepSeek、deepseek-chat 和官方接口，用户已授权并完成实际模型查询及公开片段真实调用，默认模型采用 deepseek-flash。确定性模拟服务用于异常和授权回归，真实模型验证单独记录实际供应商与结果。

完整设计位于 docs/superpowers/specs/2026-11-14-v0.2-design.md。
