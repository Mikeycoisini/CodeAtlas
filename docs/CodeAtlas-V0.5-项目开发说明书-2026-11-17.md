# CodeAtlas V0.5 项目开发说明书

版本为V0.5规划稿，编制日期2026-11-17。供后续开发agent、测试及维护者执行前评审和拆分任务使用。依据[最新剩余复核](D:/CodeAtlas/docs/reports/CodeAtlas-V0.1-V0.4-Remaining-Review-2026-11-17.md)及[架构方案三说明](D:/CodeAtlas/docs/CodeAtlas-架构总览与后续能力开发说明-2026-11-16.md)。用户已选择交互总览＋archify导出；本说明书将其安排为V0.5主目标，具体首批接口与范围为实施建议。

## 1. 版本目标

用户导入Java／Spring Boot项目后，可以先看清系统由哪些应用、工程／业务模块及外部组件组成，再下钻到当前已有类／方法与固定源码证据，并导出可离线查看的架构说明。AI入口易发现，性能瓶颈及发布链路可测量。

原始源码、固定快照、索引代次、来源与证据等级继续由CodeAtlas负责；React Flow与archify共享同一架构投影。已有文档、知识、训练、复习和引导继续可独立使用。

## 4. 数据契约与接口建议

建议ArchitectureDocument包含schemaVersion、projectId、snapshotId、generationId、analyzerVersion、projectionId／digest、nodes、edges、groups、evidence、diagnostics及coverage。节点包含稳定id、kind、名称、职责、技术信息、parentId及evidenceIds；种类至少APPLICATION、MODULE、COMPONENT、DATASTORE、EXTERNAL_SERVICE及UNKNOWN。

关系包含source、target、kind、status、reason和evidenceIds。配置事实、规则候选、AI候选和用户确认分别存来源。CONFIRMED仅表达可核对的具体事实，例如“文件配置声明了Redis”；实际启用和运行连接另需运行证据。

证据绑定固定文件哈希、范围、可选符号、解析规则。分组和人工说明采用独立覆盖层及revision，原始投影继续可查。布局和视口与事实分离。

建议只读GET /api/snapshots/{snapshot}/architecture，接受generationId、perspective、focusId、depth及limit，响应实际固定代次和截断／覆盖信息。导出POST /api/architecture/exports接受projectionId／digest、格式、范围、主题和幂等键，使用任务查询及下载接口。所有名称为提案，形成OpenAPI／Schema后作为实现基线。

## 5. V05-01 架构提取与投影

涉及analysis、snapshot、graph、store，建议新增architecture领域。复用固定快照读取和身份验证，提取模块可拆ProjectStructureAnalyzer、ArchitectureProjection等，依项目约定命名。

- [ ] 确定单模块、多模块、混合前后端、无配置及条件组件的独立预期样本。
- [ ] 静态解析pom／受限Gradle声明、启动类、Controller／Service／Repository角色、选定application配置、package.json及部署文件。
- [ ] 解析器使用大小／深度／数量限额，XML关闭外部实体，YAML安全加载。凭据、认证URL和敏感配置值过滤。
- [ ] 环境占位符、多个profile和条件装配保留环境及未确定状态，避免跨环境拼接成确定部署。
- [ ] 生成稳定节点／关系和证据，按明确工程／包结构构造初始业务模块；可选AI命名走原预览授权及候选采纳。
- [ ] 实现固定代次查询、分页／截断、跨快照拒绝、未知对象及诊断，保留旧版本恢复。

验收为每个节点／边可定位来源，重复生成身份稳定，缺失配置给出范围说明，静态分析不执行项目脚本。新持久化结构通过前向迁移，兼容现有所有代次。

## 6. V05-02 交互架构总览

新增清晰“架构总览”入口。复用React Flow、Worker、主题和现有源码导航；建议architecture目录独立承载新页面及DTO。

- [ ] 首屏突出应用、模块及外部组件，职责文字对应实际信息，分组容器与技术层可切换。
- [ ] 系统→应用→模块→类型／方法下钻，证据侧栏显示来源、状态、规则及限制。
- [ ] 点击分组展示成员，点击具体来源跳固定快照，浏览器后退恢复原总览。
- [ ] 搜索、缩放、方向、自环、孤立节点、边界计数及键盘等价列表完善。
- [ ] 请求、布局、证据、拖拽和视口按项目／快照／代次／视角隔离，旧响应丢弃。
- [ ] 覆盖中文／长标签、循环、复杂分组、窄屏、深色及布局失败恢复。

验收采用真实样本截图、布局断言和浏览器完整下钻路径，现有五类图形继续回归。

## 7. V05-03 archify隔离验证及导出

实现前固定组件来源、版本、LICENSE及子依赖。本机技能可供研究，但产品运行所需组件应随项目配置和交付。当前本机包private，不能直接据其存在承诺所有用户可安装。

- [ ] 用同一ArchitectureDocument样本转换archify JSON，验证schema、布局、中文、分组及证据状态。
- [ ] 对比受控CLI和渲染模块嵌入两种集成方式，记录体积、部署、可维护性与权限边界，形成ADR。
- [ ] 提供HTML与首个实际通过的图片格式，其他格式按能力矩阵启用；工件带快照、代次、范围及渲染器版本。
- [ ] 独立临时目录、固定参数、超时／输出限额、幂等／取消、工件原子发布及下载权限。
- [ ] 离线HTML提供证据摘要；回本机源码链接不携带token，读取继续通过应用授权。源码嵌入范围由用户显式选择。
- [ ] 验证脚本／标签注入、敏感路径、资源完整、字体、裁切、失败保留旧工件及清理边界。

验收以实际validate／deliver退出码和生成物为准。同一投影的交互图与导出节点、边、状态及来源一致，布局差异可解释。新导出不默认产生外部模型请求。

## 8. V05-04 AI入口与类图收尾

统一AI助手展示公开连接／模型就绪状态，提供解释、出题、理解题反馈、实践反馈和引导快捷入口。源码页提供明显AI操作，未选来源时提示选择。复用已有面板，保持当前身份及深链接，离线可用手工功能。

GraphIndex.classNode当前最多50成员，补截断提示和完整成员浏览，确保字段、构造器、方法、visibility和typeText表现一致。旧索引缺字段时降级并提示重建，历史继续可读。

验收包括首次使用、无项目／密钥、服务断线、跨项目切换、配置变化、拒绝与取消、长成员类、深浅主题及键盘路径。AI入口功能可发现性由真实用户操作路径及截图确认。

## 9. V05-05 性能与持续集成

已有合成样本导入约90～154秒／540文件、类图P95约1.39秒。先重现相同设备／样本／配置下的瓶颈，分析目录校验、双扫描、哈希和成员归属遍历开销，再选择缓存／批处理等最小优化。

目录校验和哈希优化保留穿越、链接／重解析点、扫描变化及内容篡改检测。CLASS成员投影优化保留归属歧义、重复类型和计数正确性。性能目标在基线测量后、动手优化前记录，报告P50/P95、重复次数、错误率、资源和冷暖状态，避免用不同条件比较。

补Java／MySQL／前端／Python／E2E分层CI。单次本地runner需在独立环境跑通；远端执行与发布／push沿用对应授权。浏览器兼容范围覆盖esnext构建目标，Terser等开发依赖也记录许可及锁文件。

验收为行为安全回归和同条件测量均通过，完整CI执行有可复现日志。性能基线与达到发布门槛分别给结论。

## 10. V05-06 P1图形子批次

流程图首批限定选定方法的顺序、条件、循环、返回和异常；跨方法业务解释单独表示展开范围和未知分支。时序图从选定入口有界展开调用，区分源码顺序与真实运行顺序，异步、多实现、递归和异常保留明确语义。

UML关联／聚合／组合／多重性按有证据的规则逐项启用，字段集合只能形成对应候选，生命周期未知继续标注。每类图在开发前形成Schema、样本、来源跳转及独立验收清单，复用架构／导出身份模式。

这些子批次选入范围后分别收尾，未选入项不静默删除。当前V0.5最低出口仍以第2节P0为准。

## 11. 顺序、分工与验收门禁

顺序为基线收尾→V05-01数据／查询→V05-02交互→V05-03导出。V05-04可在接口明确后并行处理，V05-05贯穿开发并在最终包上收尾，P1子批次单独排期。

每任务负责人明确允许修改文件、输入输出、数据库影响和证据目录。共享Schema、迁移、GraphIndex及App入口统一集成，避免多agent覆盖修改。先写回归／失败预期，再实现，保留原Java行为和现有学习调用者兼容。

版本出口需满足以下各项。

- [ ] 架构总览的系统组成和下钻在至少两个明确范围的Java／Spring Boot样本通过，包含多模块及外部配置声明。
- [ ] 导出成功可离线打开，内容与交互图投影一致，安全／失败／取消测试通过。
- [ ] AI入口易发现，旧学习流程、授权和身份隔离回归通过。
- [ ] 旧数据库、快照、索引、资料、训练、复习和引导升级／重启后可追溯。
- [ ] 最终H2、专用MySQL、Python、前端构建及E2E实际通过；跳过有原因和补测范围。
- [ ] dist／JAR资源一致，新增运行组件完整，实际启动最终包核对版本和哈希。
- [ ] 性能目标与安全边界具备对应证据；CI本地一次跑通，远端状态明确。
- [ ] 更新PRD追踪、scope-v0.5、OpenAPI／Schema、ADR、README、许可、验收及剩余清单。

## 12. 发布与后续边界

V0.5不自动代表V1.0发布准备已完成。私有认证、同步、自动执行、删除保留回收、产品内备份恢复、多语言及更多部署环境维护独立后续清单。V1.0还需确定支持环境、安装升级、数据策略、发布许可和可测量的总体发布门槛。

本文为可评审开发说明，接口、P0/P1分配及顺序为本次建议，当前仅完成文档编写。后续实际任务的完成依据为源码、运行结果和对应证据，历史记录继续保留各自时点。
