# ADR-008 关系人工修正与修正来源留存

日期 2026-11-15。状态：已采纳。归属 EXP-04 P1，交付版本 0.4.3。

## 决策问题

如何允许用户修正代码关系，同时保留不可变的原始分析结果、证据状态和修正来源？

## 背景与约束

- PRD EXP-04 要求用户可对说明和关系提出修正，并保留原始分析结果及修正来源。
- 当前关系由 JavaAnalyzer 写入 `relations` 表，绑定快照与已发布索引代次；重建索引创建新代次，旧代次继续可查。
- 图谱边按原始关系的 kind/status 聚合，证据面板展示原始 relation、调用点与声明目标。
- 本地单用户；修正属于用户输入，不应伪装成分析证据或改变 CONFIRMED/INFERRED/UNRESOLVED 语义。
- 既有 `MutationService` 提供幂等写入，可复用。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| A. 直接改写 `relations` 行 | 不采纳 | 丢失原始分析，破坏代次可复现性与证据链 |
| B. 追加式修正覆盖层 | 采纳 | 原始行不变；修正可查询、可追溯；请求失败不影响分析 |
| C. 新建 `origin=USER` 的关系行 | 不采纳 | 混淆分析投影与用户修正；图边、计数和证据语义需要重写 |
| D. 仅写入文档或笔记 | 不采纳 | 无法绑定具体 relation、无法表达修正结论和生效值 |

## 决策

- V8 新增 `relation_corrections`，字段包括快照、代次、关系、结论、可选修正类别／目标、理由、来源和时间。
- 结论为 `CORRECTED`、`REJECTED` 或 `UNCERTAIN`：
  - `CORRECTED` 至少修改类别或目标，且不能与原关系完全一致。
  - `REJECTED` / `UNCERTAIN` 不允许修改类别或目标。
- 修正 append-only；后一条修正覆盖显示，历史全部保留。没有改写或删除原始 relation 的入口。
- 修正绑定快照与已发布索引代次；关系必须属于该代次。请求使用 `MutationService` 幂等键。
- 关系列表返回原始字段、`corrections`、`latestCorrection`、`effectiveVerdict`、`effectiveKind` 和 `effectiveTargetText`；原始 `kind`/`status`/`targetText` 不变。
- 图谱证据条目返回 `corrections`、`latestCorrection` 和 `effectiveVerdict`；图边仍按原始分析聚合，不把用户修正伪装成分析事实。
- 前端源码页关系卡片提供“修正关系”入口，显示原始值、生效值、理由、来源、时间和历史；图谱证据面板只读展示对应修正。
- 明确不做：修正分析器输出、修改证据状态、删除历史、多人作者身份、审批流。

## 后果

**正面**：原始分析与证据状态完全保留；修正可追溯；图谱保持诚实边界；旧代次和重建不受影响；可回退。

**负面**：修正与原始关系并存需要额外查询与界面解释；图谱边不反映用户修正，需要用户在证据面板查看；修正记录没有作者身份与审批，适合本机单用户。

## 可逆性

两向门。移除修正 API、UI 与 V8 表即可回到只读关系；原始关系表、图与索引不受影响。触发重审：需要多用户作者/审批、修正影响图聚合、或需要删除/撤回历史。

## 安全与数据边界

- 修正只写 `relation_corrections`，不执行项目代码，不调用 AI，不修改 `relations`/`symbols`/`diagnostics`。
- 理由最多 2000 字符，来源最多 1000，目标文本最多 1000；拒绝未知字段和非法结论/类别。
- 代次必须属于快照且已发布；关系必须属于该代次。
- 幂等键冲突返回 409；同一键与内容重复提交返回原记录。

## 适应度函数

| 不变量 | 检查 |
|---|---|
| 原始关系不被改写 | 集成测试在修正后断言原 kind/status/targetText 不变 |
| 修正与历史可查 | 集成测试断言 relations 覆盖字段与 corrections 历史一致 |
| 幂等 | 同一键/内容返回同 ID；同键不同内容返回 409 |
| 非法内容被拒绝 | REJECTED 带修正内容、CORRECTED 无实际变化返回 400 |
| 代次绑定 | 错误代次返回 404 |
| 图证据并存 | 集成测试在 graph evidence 中找到修正并保持原始 relation |
| 修正不进入分析投影 | 代码审查与 SQL 检查：只写 relation_corrections |

## 职责

用户提交修正与理由；后端维护者负责校验、幂等、代次绑定与原始数据保护。本地检查路径为 `mvn test`、`npm run build`。代码责任：`ASSUMED: CodeAtlas 后端维护者`。

## 后续

多用户作者与审批、修正撤回、修正影响图聚合、跨代次对照与浏览器专项验收，需在后续设计与 ADR 中单独确认。
