# ADR-004 复习调度、学习证据与可选引导

日期 2026-11-15。状态 已采纳，用户批准V0.4完整设计。

## 背景

既有Java/MySQL负责资料、固定来源与训练提交，Python提供经授权的模型接口。V0.4需要确定性调度、逐次历史与独立的个人掌握记录。浏览和AI建议在产品中分别保留其来源。

## 选择

采用Java原生 `io.github.open-spaced-repetition:fsrs:1.0.0`，算法标识FSRS6_JAVA_1_0_0，固定配置DEFAULT_V1。Java应用保存UTC毫秒、状态及版本，库承担纯计算。参数为库的21项默认值、保持率0.9、学习步长60/600秒、重学600秒、最大36500天，关闭fuzzing并显式提供时间与内部cardId=0。业务使用CodeAtlas UUID。

每次评分原子保存ReviewEvent、ReviewState、Attempt终态以及冻结知识版本的Evidence与掌握投影。卡片实质内容改变后，由用户确认进入新epoch；旧题目与事件保留。揭示后原回忆冻结，评分由用户自报。

知识内容、个人学习事实和推导判断分表保存。规则EVIDENCE_V1说明依据，支持撤回错误关联并保留历史，按知识revision区分当前与历史证据。

可选引导采用六个稳定步骤，支持调整、跳过、暂停、退出恢复。AI调整通过LEARNING_GUIDE用途、完整预览与逐次授权生成候选，按guideId/revision绑定，显式采纳并保留用户步骤状态。

## 候选比较

| 路线 | 适配与维护 |
|---|---|
| A 自研算法 | 需维护算法与数学回归，当前收益不足 |
| B Java库 | 直接复用现有运行时与事务边界，用户已选择，六项PoC通过 |
| C Node/ts-fsrs服务 | 算法选择较多，增加进程、超时与跨服务恢复 |
| C Python库 | 可复用已有Python运行时，同时增加复习计算的跨服务依赖 |
| D 提取算法源码 | 需要持续同步上游、维护构建和许可声明 |
| E Fork | 维护范围大于当前所需纯计算适配 |

## 迁移与恢复

V4新增复习、证据、引导表，为mutation_requests增加可空response_payload供新命令保存精确响应。既有写入可继续省略该字段。MySQL默认REPEATABLE READ下，等待业务锁后使用当前读取获得版本及事实。

算法和参数升级采用新配置及前向迁移，旧事件保留原参数。关闭新入口时保留原卡片和事件。数据库与快照目录配套备份，迁移/重启在独立3307实例验收。
