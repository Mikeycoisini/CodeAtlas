## 任务与题目

TrainingTask 包含 id、title、goal、constraints、acceptanceCriteria、status、revision、tags、sourceIds、questions，以及创建/更新时间。状态为 DRAFT、ACTIVE、ARCHIVED，删除采用软删除。列表支持搜索、状态过滤与分页。

每次有效创建/修改保存不可变任务版本。当前任务行保存最新版本指针和生命周期状态，training_task_revisions 保存完整规范化定义、来源元数据和内容摘要。版本关联固定 sourceIds，包含项目、快照、代次、文件哈希和范围。每个任务1至6个来源，属于同一快照与代次，允许跨文件。

任务可含最多10题。草稿允许题目不完整，发布须具备目标、验收条件、有效来源和至少1道完整题目。题目包含稳定UUID、category、format、prompt、options、correctAnswer、referenceExplanation、hints。

category 支持 CODE_READING、CALL_CHAIN、ERROR_JUDGMENT。format 支持 SINGLE_CHOICE、TRUE_FALSE、SHORT_ANSWER。选择题2至6个唯一选项，正确答案指向有效选项ID。判断题答案为布尔值。开放题提供参考答案与解释，支持用户自评。

字段上限为标题200字符，目标/约束/验收条件各4000字符，题干4000字符，选项正文500字符，参考答案4000字符，解释8000字符，每题最多5条1000字符提示，标签最多10个。仍受实际1 MiB请求体上限保护。

编辑采用 revision 乐观锁。相同创建幂等键和内容返回原结果，键与内容冲突返回409。新版本和归档保留历史作答的旧版本。归档或删除禁止开始新的尝试，已开始的尝试可继续，历史记录可读。删除不级联销毁版本、尝试或反馈。

## 作答与记录

TrainingAttempt 绑定 taskId、taskRevision、taskDefinitionDigest 和来源身份，状态为 DRAFT、SUBMITTED、SKIPPED。开始时锁定有效任务版本，更新任务后已有尝试继续使用其冻结版本。

用户可保存作答草稿、逐题跳过、提交整次作答或跳过整次尝试。作答草稿通过 revision 更新，提交后回答和其摘要固定。用户重新作答创建新attempt。提交接口使用幂等键，重复同内容返回同一提交，终态冲突和旧版本更新返回409。

每次提交保存题目、回答、跳过标记、提交时间、内容摘要、来源身份及逐题结果。选择/判断题由服务器对照冻结答案生成 CORRECT、INCORRECT、UNANSWERED 或 SKIPPED，并标明 RULE_BASED。开放题初始为 NEEDS_REVIEW，可追加 USER_SELF_REPORTED 自评 UNDERSTOOD、PARTIAL 或 NEEDS_REVIEW 及个人复盘。

结果摘要分别显示客观题情况、开放题待复核和跳过数量。自评、规则结果和AI建议各自保留，个人掌握度由后续证据模型定义。

## 提示与答案查看

作答页面默认只返回题干、选项、来源和提示数量。编辑入口提供题目作者所需的完整定义。单用户自学模式中，查看记录只覆盖本次尝试内通过应用入口发生的操作。

提示与参考答案通过明确按钮按需查看。服务端先为attempt记录对应question的 HINT_VIEWED / REFERENCE_VIEWED 事实，再返回内容。重复请求可幂等，记录不可随页面刷新消失。查看提示和参考答案均可发生在提交前或提交后。

提交时在同一尝试锁内冻结 assistanceAtSubmission，后续查看参考答案保持原提交标记。页面显示“提交前已查看提示/参考答案”，仍允许用户继续、跳过或重试。浏览和揭示操作均不自动写入掌握度。

## AI 出题与辅助反馈

扩展现有生成链路支持 EXPLANATION、TRAINING_QUESTIONS 和 TRAINING_FEEDBACK 三个 operation。旧请求缺少operation时按 EXPLANATION 处理，旧解释结果与已保存文档继续可读。新增purpose和operation由服务端确定，公开解释接口保持其原输入语义，训练上下文经训练服务核对后构造。

Python GenerationRequest 增加有默认值的operation，服务根据operation选取固定提示和严格结构。contextJson中包含相同operation并受摘要保护。配置指纹协议版本递增，使配置/协议变化后的旧预览要求重新准备。Java与Python在发送前再次核对operation、摘要、指纹和到期时间。

TRAINING_QUESTIONS 输入为固定来源、学习目标、题目数量1至5和题型偏好。输出可编辑任务草稿，包括题目、参考答案、解释、提示、源码引用及不确定项。用户将候选应用到编辑器并确认保存/发布。AI候选不自动替换任务或发布，新生成与人工编辑并存。

TRAINING_FEEDBACK 仅针对已提交attempt中的指定question。服务从冻结版本、不可变回答和提交前帮助标记构造上下文。输出 strengths、gaps、explanation、suggestedVerdict、引用和不确定项，标明 AI_ASSISTED。suggestedVerdict 为 CORRECT、PARTIAL、INCORRECT 或 UNSURE。规则结果和自评保留各自来源及历史。

两类操作均采用完整外发预览、显式授权、15分钟有效期、24,000字符/64 KiB上下文预算、最多4096输出tokens、幂等排队、取消与迟到结果保护。预览包含实际发送的题目、参考答案及用户回答。源码、作答和引用之外不增加工具执行能力。AI异常时手工任务、作答和已有反馈继续可用。

复用引用校验，将共同校验逻辑用于解释、出题和反馈结构。伪造/越界引用标记INVALID；出题候选应用到任务前要求至少一条已校验来源，用户仍须核对题目与答案语义。AI反馈的引用状态与建议正确性分别展示。

训练上下文通过 training_ai_requests 记录 contextId、operation、可用的taskRevision/attemptId/questionId，任务版本可保留出题generationId。关联须由服务器验证。训练用途的生成结果在文档保存入口返回类型不匹配，避免跨用途误用。

## 数据与服务

新增 V3 迁移，保留 V1/V2。表为 training_tasks、training_task_revisions、training_task_sources、training_attempts、training_attempt_events、training_self_assessments、training_ai_requests。使用现有MySQL及JDBC事务，保留外键和唯一约束。

training_tasks 保存当前revision与生命周期，版本表以(task_id,revision)唯一。attempts 外键绑定冻结版本，草稿回答可变，提交后的回答/结果/摘要固定。揭示事件和自评追加保存并具幂等键。AI上下文关联已有 ai_contexts，生成状态仍由 ai_generations 持久化。

幂等操作可复用 mutation_requests 的基础表与校验模式，operation使用独立命名，禁止一个键跨操作复用。所有规范化、摘要和版本检查由服务器完成。揭示、提交和终态操作锁定同一attempt，保证帮助记录与提交边界一致。

历史版本和尝试展示应容忍源码文件存储不可用，保留已保存题目、回答及来源元数据并显示证据不可用状态。新任务保存和AI预览仍需验证来源。该降级不会把不可读来源标为已验证。

## API 草案

- GET/POST /api/training/tasks，GET/PUT/DELETE /tasks/{id}，GET /tasks/{id}/editor，GET /tasks/{id}/revisions/{revision}。
- POST /tasks/{id}/attempts 开始，GET /api/training/attempts 查询历史，GET/PUT /attempts/{id} 恢复/保存草稿。
- POST /attempts/{id}/submit、/skip、/reveal、/self-assessments 分别提交、跳过、揭示及追加自评。
- POST /api/training/ai/contexts 准备出题上下文，POST /attempts/{id}/questions/{questionId}/ai-context 准备辅助反馈上下文。
- 授权、生成查询及取消继续使用 /api/ai/consents 与 /api/ai/generations。

API具体字段、错误码和分页写入contracts，并覆盖旧客户端兼容性。任务管理与作答入口的DTO区分编辑所需定义与默认可见题目，帮助内容通过揭示接口返回。

## 前端

新增“训练”导航及训练工作区，包含任务搜索/过滤、编辑、作答与历史记录。源码方法入口增加“创建训练任务”，预填固定来源。手工编辑器管理任务目标、约束、验收条件及多题内容，提供保存草稿、发布、归档和删除。

作答界面支持选项、判断与开放回答，显示保存草稿、逐题跳过、提交和本次帮助记录。结果页显示逐题反馈来源、自评、AI辅助反馈和重新尝试。来源支持精确历史跳转及已有手动源码检查。

训练AI对话框复用现有预览/授权和生成生命周期逻辑，分别呈现出题候选和辅助反馈。用户可编辑候选后保存。trainingAiGenerationId 与旧 aiGenerationId 分开恢复，避免解释界面把训练结果当讲解读取。

URL区分trainingTaskId、trainingAttemptId、编辑/作答模式和生成身份。读取使用请求取消，异步写入和候选应用检查当前实体/操作代次，浏览器回退后迟到结果保持原身份。前端采用现有主题变量、侧栏、窄屏布局与Monaco来源定位。

## 验收

先建立当前基线，再用TDD覆盖任务草稿/发布校验、搜索与归档、幂等、乐观锁、旧版本作答、草稿恢复、揭示/提交并发、终态提交和历史恢复。错误源码归属、非法选项、伪造结果来源和跨用途生成关联应拒绝且事务回滚。

Python用MockTransport和本机fake覆盖新结构、原解释兼容、错误JSON/引用、拒绝/过期/取消及预算，断言未授权请求数为0。AI失败后人工任务和回答可恢复。

浏览器贯通源码建题、手工发布、提示/答案、作答与跳过、规则结果/自评、AI出题候选、提交后AI反馈、刷新/回退隔离和旧快照跳转。H2、专用MySQL迁移/重启与最终JAR均回归。既有源码探索、解释、知识和卡片入口继续参与全量测试。

本轮报告标明已完成的V03-01/V03-02子范围和后续阶段能力，记录模拟/真实模型的实际状态。真实模型联调沿用明确授权范围，执行前核对具体公开样本和费用上限。
