# CodeAtlas V0.1 设计

状态为用户已批准，主体实现完成。数据库路线已确认，其他细节属于已批准设计中的实施建议。依据上级目录 PRD V1.0、总体与步骤实施计划 V1.1 及 scope-v0.1.md。源码位置按用户后续要求拆分为 D:/CodeAtlas/CodeAtlas后端 和 D:/CodeAtlas/CodeAtlas前端。

## 目标与使用场景

面向本地个人开发者，完成获授权 Java / Spring Boot 项目的导入、快照、静态索引与源码探索。用户可以搜索事务方法，查看原始源码、准确行号、局部关系、分析证据和失败原因，并切换历史快照。对应 V01-01 至 V01-07 及 IMP-01 至 IMP-04、EXP-01、EXP-02。

后续阶段依照既有路线交付 AI、知识、练习与复习。本次优先交付文件树、符号搜索、源码和局部关系。

## 已确认方案与备选

用户确认使用本机 MySQL 8.0，采用 React + TypeScript、Spring Boot 和 JavaParser。

曾考虑 PostgreSQL 与 MySQL。PostgreSQL 与较新的候选技术方案一致，需要准备服务。MySQL 可复用正在运行的 MySQL80 服务，PRD 中也保留该选项。用户选择 MySQL，以减少运行环境准备工作。

建议以本地单用户方式部署，监听回环地址。前端采用 Vite 与只读 Monaco，后端采用 Spring Web、JDBC、Flyway、JavaParser / Symbol Solver。依赖版本由实施者查询官方资料、检查运行兼容性后固定并记录。当前 Java 24.0.2、Node 24.15.0、Maven 3.6.3 是环境观察值。

## 工程结构与运行

- backend 为 Maven Spring Boot 应用，负责导入、快照、索引、任务和查询。
- frontend 为 React TypeScript 应用，开发时通过 Vite 代理 API，发布时可由后端提供静态资源。
- contracts/openapi.yaml 保存首批接口及错误、状态和分页模型。
- test-fixtures 保存固定 Java 样本及预期结果。
- docs 保存 ADR、证据契约、运行说明和验收报告。
- 专用数据目录保存不可变快照及临时写入文件，默认使用工作区下 data，支持环境变量指定。

数据库连接从环境变量读取。使用 CodeAtlas 专用数据库，Flyway 管理应用表。仅允许在专用数据库中迁移。用户名和密码由运行环境提供，日志和版本控制均排除凭据。数据库不可用时明确报告连接错误。

源码分析通过解析静态文件完成。应用自身构建和测试命令写入 README。导入项目只作数据读取。

## 导入与快照

用户在界面输入绝对目录路径并确认拥有读取授权。后端解析规范路径，验证目录存在、可读以及符合配置的导入根目录范围。根目录范围可由启动配置指定，默认允许用户通过本机界面明确提交的目录。拒绝导入应用数据目录以及其祖先目录，避免递归复制自身数据。

扫描只接收普通文件，拒绝以符号链接、Windows junction 或其他重解析点作为根目录及遍历入口。遍历过程中重复验证文件属性，保证读取目标仍在导入边界内。扫描任何失败均返回具体路径和错误码。

默认忽略 .git、.idea、.vscode、node_modules、target、build、dist、.gradle，以及明显的密钥和环境文件。忽略规则作为实际快照策略记录，可通过启动配置调整。默认上限为 20,000 个文件、单文件 2 MiB、总内容 256 MiB，达到限制时明确失败。此处阈值属于实施建议，可调整并需测试。

快照保留通过扫描规则的普通文件原始字节，源码查看与解析优先支持 UTF-8，编码错误明确展示。计算每个文件 SHA-256，按规范相对路径排序后计算带长度边界的清单摘要。清单同时包含快照策略版本。文件树中展示路径和可浏览状态。

先写临时快照目录，核对复制前后清单、内容哈希及文件元信息。若发现源文件增加、删除或修改，返回 SOURCE_CHANGED 并支持重新导入。扫描结果表示此次读取到的稳定内容集合。原始目录后续变化不会影响已发布快照。

Git 信息通过固定参数、禁用外部命令扩展的只读 git 调用获取，设置超时，路径作为独立参数传入。记录 HEAD、相对仓库根目录以及原始工作区状态摘要。支持工作树中的子目录和 linked worktree。Git 检测失败时保留 UNKNOWN 及诊断，不能静默归为 NON_GIT。完整仓库状态为 clean 且导入前后 HEAD、状态保持稳定时标记 GIT_CLEAN，其余稳定 Git 工作区标记 GIT_DIRTY。无仓库时标记 NON_GIT。内容摘要始终作为实际文件身份。

数据库唯一约束使用 project_id、manifest_hash、source_kind 和 source_revision_key，区分相同内容下不同 Git 来源身份。原路径规范化值唯一标识本地项目。相同身份重导入复用有效快照。文件发布使用同卷目录重命名，数据库只发布完整快照。进程中断遗留的临时目录与未发布记录在启动恢复时清理或标记失败，完整快照保留。导入同样作为可轮询任务执行，进度按文件统计。

## 数据模型与约束

所有实体采用 UUID 字符串标识，时间使用 UTC，界面按用户时区显示。

| 实体 | 主要字段及约束 |
|---|---|
| Project | id、name、canonical_source_path、created_at，规范路径唯一 |
| SourceSnapshot | id、project_id、manifest_hash、source_kind、commit_hash、source_revision_key、policy_version、storage_key、status、created_at，来源身份与清单联合唯一 |
| SnapshotFile | id、snapshot_id、relative_path、sha256、byte_size、encoding_status，快照与路径唯一 |
| ImportTask | id、source_path、status、progress、error_code、snapshot_id、timestamps，同规范路径活动任务复用 |
| IndexTask | id、snapshot_id、analyzer_version、status、progress、cancel_requested、timestamps、summary，快照与版本通过加锁创建活动任务 |
| IndexGeneration | id、snapshot_id、analyzer_version、task_id、published_at，每个快照至多一个已发布代次 |
| CodeSymbol | id、generation_id、file_id、kind、name、qualified_name、signature、start_line、start_column、end_line、end_column、annotations，代次内符号键唯一 |
| CodeRelation | id、generation_id、source_symbol_id、target_symbol_id 可空、target_text、kind、status、reason、evidence_file_id、range、resolver |
| FileDiagnostic | id、generation_id、file_id、code、message、range，保存解析与编码错误 |

数据库外键和查询同时约束项目、快照及代次归属。源码位置采用 1-based 行列，范围为包含末端的 AST 原始范围。符号键包含文件路径、限定类型、成员种类、名称、规范参数类型，声明位置作为无法解析或重复声明时的消歧依据。构造函数和嵌套类具有独立身份。

## Java 解析与证据

每文件独立解析，单文件语法或编码失败写入诊断。先提取声明，再建立引用与关系。解析器仅访问当前快照和 Java 运行时类型，依赖解析不执行 Maven / Gradle，缺失依赖可产生 UNRESOLVED。从快照中提取各源码根目录，重复限定类型保留歧义。Java 支持语法级别通过 PoC 明确记录，超出支持范围的文件产生诊断。

CONFIRMED 表示可以依据 AST 和确定性解析验证的声明关系或静态调用目标。INFERRED 表示基于明确框架规则得到的候选，附规则名与理由。UNRESOLVED 表示缺依赖、歧义、动态目标或未支持语法等情况。

继承和接口实现可解析时指向目标符号。调用关系区分静态编译目标与运行时目标。接口调用可记录编译期接口方法，运行时目标另外保留 UNRESOLVED，尤其 Spring 多实现时保存候选及原因。对于 V0.1 尚未实现的规则采用 UNRESOLVED，并记录覆盖边界。关系证据使用调用表达式或类型声明的准确位置。局部关系列表展示种类、状态、目标、理由和证据跳转。

## 索引生命周期和一致性

任务状态包括 QUEUED、RUNNING、SUCCEEDED、PARTIAL_SUCCESS、FAILED、CANCELLED。导入任务采用同样模型，导入失败不发布部分快照。索引至少有一个文件成功且存在文件级错误时为 PARTIAL_SUCCESS，所有 Java 文件失败为 FAILED。零 Java 文件完成为空索引并给出 NO_JAVA_FILES 提示。

每个快照最多一个活动索引任务。数据库事务锁定快照行创建任务，重复请求返回当前活动任务。成功任务的普通重复请求返回已有结果，显式 rebuild 创建新代次。FAILED、CANCELLED 和 PARTIAL_SUCCESS 可重试。解析器版本变化允许重新索引。

索引写入独立暂存代次，处理中按任务 ID 查看部分数据。终态成功或部分成功时，事务内发布整个代次。查询默认读取已发布代次。重建过程中旧代次继续可查，失败或取消时旧结果保留。保留历史代次以支持符号引用，查询支持 generationId。

取消请求记录 cancel_requested，工作线程在文件边界及发布事务内检查。取消与发布使用同一任务锁决策，已完成任务的取消请求返回终态。进程重启将遗留 QUEUED / RUNNING 标记 FAILED，错误为 PROCESS_INTERRUPTED，提供重试入口。采用单进程、有界队列工作线程，队列满时返回 TASK_CAPACITY_EXCEEDED。

## API 契约概要

接口位于 /api，JSON 字段采用 camelCase，列表使用 limit 和 offset，设置最大 limit。错误结构包含 code、message、details、requestId。路径和源码内容仅向本机用户返回。

| 操作 | 接口 |
|---|---|
| 导入与项目列表 | POST /api/imports，GET /api/imports/{taskId}，POST /api/imports/{taskId}/cancel，GET /api/projects |
| 项目快照 | GET /api/projects/{projectId}/snapshots |
| 索引创建和重建 | POST /api/snapshots/{snapshotId}/index，body 含 rebuild |
| 索引查询、取消、重试 | GET /api/tasks/{taskId}，POST /api/tasks/{taskId}/cancel，POST /api/tasks/{taskId}/retry |
| 文件列表和路径搜索 | GET /api/snapshots/{snapshotId}/files?query= |
| 文件内容 | GET /api/snapshots/{snapshotId}/files/{fileId}/content |
| 符号搜索 | GET /api/snapshots/{snapshotId}/symbols?query=&generationId= |
| 局部关系 | GET /api/snapshots/{snapshotId}/symbols/{symbolId}/relations?generationId= |
| 部分结果与诊断 | GET /api/tasks/{taskId}/symbols，GET /api/tasks/{taskId}/diagnostics |
| 健康状态 | GET /api/health |

新任务返回 202，复用终态结果返回 200。不存在或归属不匹配返回 404。输入非法返回 400，访问未授权返回 403，状态冲突返回 409，扫描大小限制返回 413，队列容量不足返回 503。文件读取通过数据库 fileId 映射，存储相对路径再次验证边界。源码响应含文件哈希、快照 ID、编码、内容及行数。

## 前端交互

首页提供项目列表、本地路径导入和当前任务状态。导入后进入探索页，顶部选择项目和快照并展示 Git 状态与内容摘要。左侧提供可展开文件树、路径搜索和符号搜索，中间展示只读源码与行号，右侧展示符号信息、局部关系和文件诊断。

点击符号定位声明范围，点击证据定位表达式。URL 保存 projectId、snapshotId、fileId、symbolId、generationId 及行号，刷新和历史导航恢复对应状态。重载搜索结果展示完整签名。快照切换清空不属于新快照的选中项。对过期网络响应进行取消或身份校验，避免显示上一次快照的数据。

任务运行时显示已处理文件数、总数和取消按钮。终态显示错误、部分成功与重试入口，保留已有索引入口。页面覆盖空列表、数据库不可用、导入失败、无 Java 文件和错误源码编码等状态。桌面布局适配窄窗口，输入、按钮和状态信息支持键盘操作及可访问标签。视觉采用清晰的开发工具布局，字体优先使用项目中可用的 Inter 与等宽字体。

## 本地访问边界

服务绑定 127.0.0.1，开发代理固定回环目标。API 验证 Host / Origin，拒绝非本机来源的状态变更请求，JSON 请求限制 Content-Type。使用本机会话令牌保护目录读取及导入操作，通过应用首页建立会话，令牌仅在运行时保存。静态资源与 API 同源，开发来源显式配置。限制请求体大小与任务并发。

导入路径、符号链接、文件数量、源码编码、Git 超时和目录变化均形成专门测试。日志只输出任务 ID、错误码和必要诊断，敏感绝对路径仅在用户请求的本机诊断中展示。

## PoC 与验收

先验证当前 JDK 与候选框架、JavaParser 的兼容性，再固定版本。以静态小型 Spring 样本验证事务注解、重载、继承、接口多实现、缺依赖、语法错误、行号和关系来源。预期结果在实现前记录，真实项目验收需要用户指定路径和版本。

后端覆盖快照稳定性、原目录保持不变、重导入去重、历史引用、路径边界、解析部分成功、任务并发、取消与恢复。MySQL 集成验证迁移、约束、事务发布及服务重启后的读取。前端执行类型检查、构建和浏览器操作，验证从正常入口完成导入至源码定位，以及重试和快照切换。

验收报告记录测试命令、环境、样本、通过与失败数、索引耗时、资源测量结果、已知语法及框架限制。真实项目尚未提供时单独标记该项待验收，交付可以运行和继续验收的版本。数据库凭据未提供时继续完成离线解析和前端验证，数据库连通及持久化联调保留真实状态。
