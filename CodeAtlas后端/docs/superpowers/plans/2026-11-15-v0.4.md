## Global Constraints

- Preserve V1/V2/V3, add V4. Local source YAML contains user configuration, release JAR uses environment template.
- Review UTC epoch milliseconds, explicit server clock, fuzz=false, desiredRetention0.9, steps60/600s, relearn600s, max36500days, fixed21 parameters and config hash.
- Review attempts freeze content and source identities. Grade commits event/state/attempt/evidence/projection atomically. History survives content changes/deletions.
- Review lock order card→state→attempt→knowledge→projection, use current reads after waits under MySQL REPEATABLE READ.
- Independent evidence keeps provenance/revisions, retractions append history. AI/skip/environment/view actions do not determine mastery.
- Guide six stable step IDs, free reorder/skip/pause/exit/resume, optional AI candidate explicitly applied.
- Existing AI budgets15min/24000chars/64KiB/max4096tokens, explicit preview/consent, protocol fingerprint increment.
- Tests use independent fixtures/databases, no external model calls. V03-03+ execution/workspace remains future scope.

## Review Focus

1. Card edits/deletes/reassignments between reveal and submit preserve the old definition and reject invalid current state. Task1 tests content and metadata differences.
2. Simultaneous grading, retries and clock rollback produce one consistent event/state. Task1/6 include H2/MySQL lock barriers and rollback.
3. Old training evidence associated after knowledge edits, duplicates or retractions uses exact knowledge revision and truthful provenance. Task2 tests version and ordering.
4. Source-less guide AI, forged step IDs and late restore/apply responses preserve current user edits. Task3/4/5 tests type, identity and restore gates.
5. Fresh reload and old data migration retain review drafts/reveals, history, source-unavailable fallback and guide lifecycle. Task5/6 browser and restart tests.
