## 2. 字段路径、单位与空值来源

真实字段链（`ReviewService` / `FsrsScheduler`）：

| 位置 | 字段 | 类型/单位 | 示例 |
|---|---|---|---|
| `GET /api/reviews/cards/{id}/state` | `dueAtMs` | epoch 毫秒 | `1795498243771` |
| 同上 | `state.due` | ISO 8601 UTC | `2026-11-24T05:30:43.771Z` |
| `GET /api/reviews/cards/{id}/history` | `items[].payload.dueAtMs` | epoch 毫秒，仅 `REVIEW` 事件有 | `1794807643649` |
| 同上 | `items[].payload.after.due` | ISO 8601 UTC | `2026-11-16T05:40:43.649Z` |
| MySQL `review_states` | `due_at_ms` | BIGINT epoch 毫秒 | `1795498243771` |
| MySQL `review_events.payload` | `dueAtMs` / `after.due` | 毫秒 / ISO 字符串 | 同上 |

- 单位统一为 **epoch 毫秒**；ISO 字符串使用 UTC（`Z`），界面和脚本展示本地时间时再换算。
- `ENROLL` 事件没有 `dueAtMs`（首次加入尚未评分），但有 `after.due`；把 `ENROLL` 当成“第一次评分”会取到空值。
- 原导出脚本未入库，无法逐字复原；按产物中的 `firstDueAt` 字段名与现有结构复现，`state.firstDueAt`、`history.items[0].dueAt`、`history.items[0].payload.dueAt` 均不存在，读取结果都是 `null`。候选错误路径与正确路径见 [null-reproduction.json](evidence/planning-followup-2026-11-16/f05/null-reproduction.json)。

### 4.1 取证脚本的两个编码坑（本轮实测）

1. **Windows PowerShell 5.1 读取无 BOM 的 UTF-8 `.ps1` 会按 ANSI（GBK）解码**，中文请求体在脚本解析阶段即损坏。脚本必须保存为 **UTF-8 with BOM**；本轮两个脚本均已加 BOM。
2. PowerShell 把 `‘ ’` 视为单引号定界符，中文正文里使用弯单引号会导致语法错误；固定样本改用【】等非定界符标点。
3. `mysql` 客户端的 `source <含中文路径>` 在 Windows 下打不开文件（ANSI 路径解码），本轮改用 .NET `Process` 以字节流写入 stdin 完成恢复，不经过命令行路径。
