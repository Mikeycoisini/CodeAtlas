## 已实现范围

- `PRACTICE_SUBMISSION`：绑定练习提交，`USER_PRACTICE`、eligible=false、PRACTICE_ARTIFACT；记录提交摘要、变更文件数、任务／快照和报告数量。
- `PRACTICE_TEST_RESULT`：绑定用户测试报告，`USER_REPORTED`；PASSED 正、FAILED 负、ERROR/TIMEOUT eligible=false。
- 掌握规则 `EVIDENCE_V2`：两次用户报告通过的实践测试达到 SUPPORTED；最新 FAILED 进入 NEEDS_REVIEW；ERROR/TIMEOUT 不改变状态。
- 代码练习面板增加“关联代码提交到知识”和“关联该报告到知识”；进度视图显示实践通过次数、提交摘要、报告详情和限制说明。
- 复用现有证据幂等、撤回、知识版本和历史；无新 API、无迁移。

## 说明

- 提交只进入历史与关联展示，不直接提高掌握度；掌握判断的强度低于系统独立执行。
- ERROR/TIMEOUT 保留来源语义但不计为能力失败，符合 PRD PR-05 的结果区分要求。
- 本轮全量测试在 Maven JVM 内以 `-DforkCount=0` 运行：本机 surefire fork 在测试启动阶段出现原生内存分配失败（G1 virtual space），单独运行受影响测试与全量结果均通过；该参数仅是本机环境绕行，不改变测试内容。
- 决策见 `docs/adr/ADR-009-practice-evidence.md`；契约见 `contracts/v0.4-review-evidence-guides.md`；范围见 `docs/requirements/scope-v0.4.5.md`。

## 修订 2026-11-16：计数单位

原 `EVIDENCE_V2` 按报告 ID 统计实践通过次数，同一提交的两份 PASSED 报告会被算作两次通过。经复核 ADR-009，“两次实践测试”应代表独立练习，现调整为按提交 ID 去重并升级为 `EVIDENCE_V3`：同一提交的多份报告只计一次，历史 `EVIDENCE_V2` 判断保留原 rule_version。`ProgressIntegrationTest.practiceSubmissionAndUserReportsBecomeSeparateKnowledgeEvidence` 已覆盖同提交两份报告仍为 PRACTICING、第二份独立提交通过后达到 SUPPORTED。
