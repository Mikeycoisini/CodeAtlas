# V0.4.3 关系人工修正契约

依据 EXP-04 P1 与 `docs/adr/ADR-008-relation-corrections.md`。

## 端点

`POST /api/snapshots/{snapshot}/relations/{relation}/corrections`

```json
{
  "generationId": "uuid",
  "verdict": "CORRECTED",
  "correctedKind": "RUNTIME_CALL",
  "correctedTargetText": "sample.AuditService.audit",
  "reason": "人工核对调用点与运行时目标",
  "source": "PaymentService.java:L8",
  "idempotencyKey": "uuid"
}
```

- `generationId` 必填，必须属于该快照且已发布。
- `verdict` 取 `CORRECTED`、`REJECTED`、`UNCERTAIN`。
- `CORRECTED` 至少提供 `correctedKind` 或 `correctedTargetText`，且不能与原关系完全一致。
- `REJECTED` / `UNCERTAIN` 不得提供修正类别或目标。
- `reason` 必填，最多 2000 字符；`source` 可选，最多 1000 字符。
- `idempotencyKey` 必填，最多 100 字符；同一键与内容重复返回原记录，同键不同内容返回 409。

`GET /api/snapshots/{snapshot}/relations/{relation}/corrections?generationId=...`

返回修正历史数组，按 `createdAt` 与 `id` 升序。

## 关系列表覆盖字段

`GET /api/snapshots/{snapshot}/symbols/{symbol}/relations` 的每个 item 保留原始字段，并追加：

- `id`：原始 relation ID。
- `corrections`：该关系的全部修正历史。
- `latestCorrection`：最新一条修正或 null。
- `effectiveVerdict`：最新修正结论或 null。
- `effectiveKind`：`CORRECTED` 且提供类别时为新类别，否则为原始 kind。
- `effectiveTargetText`：`CORRECTED` 且提供目标时为新目标，否则为原始 targetText。

`REJECTED` / `UNCERTAIN` 不改变 effective kind/target，只通过 verdict 表达用户意见。

## 图谱证据

`GET /api/snapshots/{snapshot}/graph/edges/{edge}/evidence` 的每个 item 追加：

- `corrections`、`latestCorrection`、`effectiveVerdict`。

图边仍按原始 relation 的 kind/status 聚合，不把用户修正伪装成分析证据。用户可在源码关系卡片中修正，在图谱证据中查看对应修正。

## 错误码

| 错误码 | 含义 |
|---|---|
| `INVALID_RELATION_CORRECTION` | 字段、结论、类别或内容无效 |
| `NOT_FOUND` | 快照、代次、关系或修正不存在 |
| `IDEMPOTENCY_CONFLICT` | 请求标识已用于不同操作或内容 |

## 数据与不变量

V8 新增 `relation_corrections`，外键绑定快照、代次和原始关系。修正 append-only；没有改写或删除原始 relation 的入口。修正不执行项目代码、不调用 AI、不改变 `relations`、`symbols`、`diagnostics` 或图边聚合。
