# V0.4.2 公开 GitHub 仓库导入契约

依据 IMP-01 P1 与 `docs/adr/ADR-007-github-import.md`。

## 端点

`POST /api/imports/github`

请求：

```json
{
  "url": "https://github.com/owner/repo",
  "ref": "main"
}
```

- `url` 必填，必须是 `https://github.com/{owner}/{repo}(.git)?` 根地址；`www.github.com` 归一化为 `github.com`。
- `ref` 可选，为分支或标签名称；省略或空字符串表示远端默认分支。
- 响应 `202 Accepted`，返回与本地导入相同的 Task 结构，包含 `sourceType=GITHUB` 与 `sourceRef`。

## 输入校验

拒绝以下 URL：非 https、非 github.com、包含 userinfo、query、fragment、非 443 端口、路径不是 owner/repo 根、`.`/`..` 段、超过 300 字符。

拒绝以下 ref：空串以外的非允许字符、`-` 开头、`/` 开头或结尾、`.` 结尾、包含 `..`、`//`、`.lock`，或超过 200 字符。

## 任务与重试

- 任务 `kind=IMPORT`，`sourceType=GITHUB`，`sourcePath` 保存归一化仓库 URL，`sourceRef` 保存分支/标签。
- 同一 URL 与 sourceType 的 QUEUED/RUNNING 任务复用，不重复创建。
- `POST /api/tasks/{id}/retry` 对失败或取消的 GitHub 导入使用原 URL 与 ref 创建新任务；已成功的重复导入若快照身份一致，复用已有快照。

## 克隆与快照

- staging 路径为 `CODEATLAS_DATA/github-staging/<taskId>`，克隆目录为 `<taskId>/repo`。
- 命令固定为 `git clone --quiet --depth 1 --single-branch --recurse-submodules=no --template=<空目录> [--branch <ref>] -- <url>.git <repo>`。
- 关闭 hooks、fsmonitor、untracked cache、autocrlf、symlinks、credential helper 与 LFS smudge；独立 HOME/XDG 配置；`GIT_CONFIG_NOSYSTEM=1`；禁止终端提示。
- 超时默认 180 秒，可由 `CODEATLAS_GITHUB_TIMEOUT` 覆盖；任务取消在克隆等待循环中生效。
- 克隆完成后由 `SnapshotScanner` 重新扫描并复制到不可变快照；`.git`、密钥文件、构建产物按现有策略跳过；源文件数量/大小/总量限制不变。
- 成功、失败、取消后删除 staging；快照保留解析后的 commit。

## 错误码

| 错误码 | 含义 |
|---|---|
| `INVALID_GITHUB_URL` | URL 不在允许范围 |
| `INVALID_GITHUB_REF` | 分支或标签名称无效 |
| `GITHUB_NOT_FOUND` | 仓库不存在或不是公开仓库 |
| `GITHUB_AUTH_REQUIRED` | 仓库需要认证，首版不支持 |
| `GITHUB_REF_NOT_FOUND` | 指定分支或标签不存在 |
| `GITHUB_NETWORK` | 无法连接 GitHub |
| `GITHUB_TIMEOUT` | 克隆超时 |
| `GITHUB_GIT_UNAVAILABLE` | 本机未安装 Git |
| `GITHUB_CLONE_FAILED` | 其他克隆失败 |
| `CANCELLED` | 用户取消 |

## 数据与安全

V7 迁移增加 `projects.source_type`、`tasks.source_type` 与 `tasks.source_ref`。不保存 token、认证头或远端凭据。远端仓库不执行构建、测试、脚本或 hook；仅支持公开仓库。
